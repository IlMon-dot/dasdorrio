# Сайт-прокладка Dasdorrio

Одна страница для шапки профиля в соцсетях. Человек приходит из ролика,
видит товар крупно на сцене в его цветах, выбирает другой товар в ленте
справа и уходит по таблетке на Wildberries, Ozon или в магазин dasdorrio.ru.
Сайт ничего не продаёт и денег не принимает.

**Адрес:** https://dasdorrio.shop/ (домен на reg.ru, DNS: четыре A-записи на GitHub Pages
и CNAME www; старый адрес https://ilmon-dot.github.io/dasdorrio/ перенаправляет сюда)

## Файлы

| `photo/` | `имя-hero.webp` герой, вырезанный из родной сцены; `имя-thumb.webp` миниатюра 200×200 (товар целиком, у наборов — только насос); `og.jpg` картинка для мессенджеров |

| `prices.js` | цены у кнопок площадок; пишет только скрипт цен по расписанию, руками не править |
| `prices-settings.json` | настройки цен: какие площадки показывать, часы сбора, оценка цены Ozon с картой |
| `scripts/prices.mjs`, `.github/workflows/prices.yml` | скрипт цен и расписание его запуска на GitHub |

Страницы политик ничего внешнего не грузят.

## Как поменять названия и ссылки

Редактор: **https://dasdorrio.shop/edit.html**. Там можно
переименовать товар, поменять подпись и адрес любой кнопки, добавить или
убрать кнопку, переставить кнопки и товары. Кнопка «Сохранить на сайт»
записывает `products.js` в репозиторий, сайт обновляется примерно через
минуту.

Один раз нужен токен GitHub (редактор запоминает его в браузере):
1. github.com → аватар → Settings → Developer settings → Personal access
   tokens → Fine-grained tokens → Generate new token
   (прямая ссылка: https://github.com/settings/personal-access-tokens/new).
2. Имя любое, срок — до года (потом создать заново так же).
3. Repository access → Only select repositories → `dasdorrio`.
4. Permissions → Repository permissions → Contents → Read and write.
   Необязательно: для кнопки «Обновить цены сейчас» там же Actions → Read and write.
5. Generate token → скопировать строку `github_pat_…` → вставить в редактор →
   «Подключить».

Токен никому не пересылать: он даёт право менять файлы этого репозитория.
Добавление новых товаров (фото, сцена, палитра) остаётся за агентом.

## Как добавить товар

Проще всего — сказать агенту: «добавь товар», дать ссылки на WB, Ozon и
магазин и 2–3 фото товара (лучше обложки с маркетплейса). Через Higgsfield
(MCP подключён) агент сгенерирует родную сцену товара по этим фото,
дорисует фон без товара, вырежет героя на его место, сделает миниатюру,
снимет палитру и допишет блок с `геройБокс`. Один товар — примерно 8–10
кредитов Higgsfield.

Вручную: открыть `products.js`, скопировать блок в фигурных скобках,
поменять `ключ`, `название`, пути к картинкам (`герой`,
`миниатюра`, `сцена`), `геройБокс`, `палитра` и `ссылки`. Порядок блоков = порядок в ленте, первым ставится то, что
продвигается сейчас. Нет товара на площадке — её строка
удаляется. Каждая ссылка — `{ вид, имя, адрес }`: вид задаёт цвет монетки
(`wb`, `ozon`, `market` — Яндекс Маркет, `shop` — dasdorrio.ru, `other` —
любая другая), имя — подпись кнопки, адрес — https-ссылка.

Палитра: `фон` — глубокий тон вуали под текстом (темнее самого товара, иначе
товар сливается с ней), `фон2` — ещё темнее, `акцент`/`акцент2` — цвета
деталей, `текст`/`текст2` — основной и вторичный текст (контраст к фону не
ниже 4,5:1), `логотип` — `светлый` на тёмной сцене, `тёмный` на светлой.

## Цены на кнопках

GitHub будит `scripts/prices.mjs` каждый час, но цены скрипт собирает один раз за час из
настроек (вкладка «Цены» в редакторе, по умолчанию 06:00 по Москве) — в первом запуске
после этого часа. Точного времени ждать не стоит: cron публичного репозитория GitHub
исполняет как получится, часть запусков пропускает, за сутки их выходит 4–6, поэтому сбор
бывает и на несколько часов позже. Лишние запуски заканчиваются за секунды без запросов
к площадкам. Собранные цены пишутся в `prices.js`, бот коммитит
файл, и GitHub сам пересобирает сайт. Руками `prices.js` не править — следующий сбор его перепишет.

| Площадка | Откуда цена | Чем отличается от цены у покупателя |
|---|---|---|
| Wildberries | официальный API продавца WB, секрет `WB_API_KEY`: цена продавца со скидкой продавца и остаток — отчёт аналитики по товарам, скидка WB — самый свежий заказ товара за 30 дней из статистики | цена = цена продавца × (1 − скидка WB), как WB сам считает цену покупателя в заказах; без WB Кошелька и личных скидок. Скидка WB — как в последнем заказе: если WB её с тех пор поменял, цена отстанет до следующего заказа. Остаток 0 — «нет в наличии» |
| Ozon | вручную: владелец вписывает цену с Ozon Картой в редакторе (вкладка «Цены», поле товара `ценаOzon`) | цена как на витрине в момент, когда её вписали; даты и автоматического скрытия нет — владелец сам меняет цену или выбирает «нет в наличии», «цена на площадке», «не показывать». API Ozon цену с картой не отдаёт, а цена продавца из него выше витрины (у багги 21 235 ₽ при 6 753 ₽ с картой) |
| dasdorrio.ru | страница товара: разметка JSON-LD, запасной вариант — мета-тег цены | точная цена магазина на момент запуска. Нет в наличии (по разметке страницы) — цены нет |

Скрипт берёт у товара только поле `площадки` и ходит только по чистым адресам;
ссылки кнопок с метками статистики он не читает, чтобы не портить статистику
переходов. Площадка не ответила — в `prices.js` остаются прежние цена и дата,
рядом пишется короткая ошибка. Сайт показывает цену, только если ей не больше 48 часов.
Данные карточек WB (`card.wb.ru`) с 22.09.2026 отдаются только браузеру, прошедшему
антибот-проверку WB, поэтому цены WB скрипт берёт только из официального API продавца.
Статистика WB не ответила — берётся скидка WB из прошлого сбора (`скидкаWB` в `prices.js`),
если ей не больше 30 дней.

**Идентификаторы** — поле `площадки` у товара в `products.js` (или вкладка «Цены»
в редакторе — туда можно вставить обычную ссылку на товар, метки отбросятся): `wb` — артикул WB (цифры), `ozon` — SKU (цифры из
адреса `ozon.ru/product/<SKU>/`), `shop` — адрес товара на dasdorrio.ru без «?» и «#».
Идентификатор с «?», «#» или `utm` скрипт отвергает с ошибкой «неверный
идентификатор». Нет идентификатора — у кнопки не будет цены.

**Настройки** — `prices-settings.json`:
- `показывать: false` — площадку не опрашивать, цены у её кнопок не будет;
- `ozon.показывать: false` — скрипт Ozon не опрашивает: цену Ozon задаёт владелец вручную
  (поле товара `ценаOzon`); `ozon.оценкаКарты` больше не используется.

**Вторая строка в кнопке на сайте.** WB и магазин: свежая цена из `prices.js` (не старше
48 часов); «нет в наличии» — только если площадка сама так ответила; «цена на площадке» —
если цену получить не удалось или она устарела; нет записи — второй строки нет. Ozon: то,
что выбрано в редакторе — цена («1 322 ₽»), «нет в наличии», «цена на площадке» или ничего;
поле не заполнено — «цена на площадке». Остатки магазина dasdorrio.ru берутся с Ozon,
поэтому если скрипт увидел в магазине «нет в наличии» (страница товара открылась, а цены
или остатка нет), у Ozon тоже «нет в наличии» — при режимах «Цена» и «Цена на площадке»;
когда в магазине снова есть цена, у Ozon сама возвращается вписанная цена. Если магазин
просто не ответил, у Ozon остаётся вписанная цена. Цену вписывать целыми рублями до 10 млн; «1 322 ₽»
можно вставить с витрины как есть, две цены подряд редактор не примет.

**Ключ WB** — нужен: без него у WB в `prices.js` ошибка «нет ключа WB_API_KEY», а через
48 часов у кнопки WB — «цена на площадке». Как завести:
1. Кабинет продавца WB → Настройки → Доступ к API → создать токен: тип «Базовый»,
   категории «Аналитика» и «Статистика», «Только на чтение». Персональный токен не
   подходит: по правилам WB его нельзя использовать в облачных сервисах, а скрипт
   работает на серверах GitHub.
2. github.com/IlMon-dot/dasdorrio → Settings → Secrets and variables → Actions →
   New repository secret: `WB_API_KEY` — токен.
3. Проверить ручным запуском (ниже): в логе у WB цены вида
   «6260 ₽ (продавец 8943 ₽ − скидка WB 30 % по заказу 21.09)», а не ошибка.

Базовому токену WB разрешает аналитику 2 раза в час и статистику раз в 3 часа: второй
ручной запуск в эти 3 часа возьмёт скидку WB из прошлого сбора. Токен истёк или отозван —
в редакторе ошибка «ключ WB_API_KEY не принят»: создать новый и заменить значение секрета
(кнопка Update). Ключ никуда больше не вставлять — ни в файлы, ни в редактор, ни в чат.

**Ключ Ozon** — сейчас не нужен: цена Ozon вписывается вручную, скрипт Ozon не опрашивает.
Секреты можно оставить на случай, если вернуться к автоматическому сбору. Как завести ключ
(один раз, дальше — раз в 3 месяца):
1. Личный кабинет продавца Ozon → Настройки → API ключи → создать ключ с ролью
   только на чтение: скрипту хватает читать товары и цены.
2. Скопировать Client ID и сам ключ.
3. github.com/IlMon-dot/dasdorrio → Settings → Secrets and variables → Actions →
   New repository secret: `OZON_CLIENT_ID` — Client ID, `OZON_API_KEY` — ключ.
4. Проверить ручным запуском (ниже): в логе у Ozon должны быть цены, а не «нет ключа».

Ключ никуда больше не вставлять — ни в файлы, ни в редактор, ни в чат. Ozon
выдаёт ключ на 3 месяца: потом создать новый и заменить значение секрета
`OZON_API_KEY` (кнопка Update). Пока ключа нет, у Ozon в `prices.js` ошибка
«нет ключа» и цена у кнопки не показывается.

**Ручной запуск** — кнопка «Обновить цены сейчас» во вкладке «Цены» редактора (токену
нужно право Actions → Read and write) или Actions → Цены → Run workflow. Через пару минут новые цены на сайте.

**Расписание засыпает.** В публичном репозитории GitHub отключает расписание после
60 дней без активности (перед этим присылает письмо). Если цены перестали
обновляться — Actions → Цены: при надписи об отключении нажать Enable workflow.

**Логи видны всем.** Репозиторий публичный, лог запуска может открыть любой. Поэтому
скрипт не печатает ключи, заголовки и ответы площадок — только цены, SKU и короткие
ошибки с HTTP-кодом; значения секретов GitHub в логе ещё и закрывает звёздочками.

**Калибровка оценки с Ozon Картой** (14.09.2026 не прошла: расхождение с витриной до 11 %, поэтому цена Ozon вручную). При запуске с ключом скрипт пишет в лог по каждому
SKU кандидатов: `ozon_index_mul`, `ozon_index_div`, `external_mul`, `external_div`,
`self_mul`, `self_div` — расчёты от минимальной цены и индекса цены (умножением и
делением). Чтобы включить оценку: взять кандидатов из лога, на ozon.ru посмотреть
зелёные цены с картой тех же товаров, выбрать кандидата, который на всех товарах
отличается не больше чем на 3 %, и записать его имя в `ozon.оценкаКарты`. На сайте
появится «≈ с Ozon Картой». Если со временем оценка разошлась — вернуть `нет`.

Проверить локально: `node scripts/prices.mjs --dry` — только лог, без записи
файла (без ключей Ozon будет «нет ключа», это нормально).

## Картинки

| Файл | Размер | Лимит |
|---|---|---|
| `имя-hero.webp` | вырезка из родной сцены, до 1200 px, без фона; положение в кадре — `геройБокс` | 150 КБ |
| `имя-thumb.webp` | 200×200, товар целиком, без фона | 18 КБ |
| `bg/имя.webp` | родная сцена без товара, квадрат 1400 px | 130 КБ |

Первый экран целиком должен весить не больше 300 КБ.

GitHub Pages разрешает браузеру держать файлы 10 минут, поэтому после замены
картинок агент поднимает метку `ВЕРСИЯ_КАРТИНОК` в `products.js` (картинки
грузятся с `?v=метка`), данные грузятся с меткой минуты, а страница сама
перезагружается один раз, если на сервере она новее.

## Метки UTM: откуда пришли

Метка ставится **до** решётки, иначе она не работает:

- верно: `https://dasdorrio.shop/?utm_source=instagram&utm_medium=bio#drakon`
- неверно: `https://dasdorrio.shop/#drakon?utm_source=instagram` — всё после решётки
  считается именем товара, метка теряется полностью.

Заготовки под шапки профилей:

| Где ссылка | Адрес |
|---|---|
| Instagram, шапка | `https://dasdorrio.shop/?utm_source=instagram&utm_medium=bio` |
| TikTok, шапка | `https://dasdorrio.shop/?utm_source=tiktok&utm_medium=bio` |
| YouTube, описание ролика | `https://dasdorrio.shop/?utm_source=youtube&utm_medium=video&utm_campaign=drakon#drakon` |
| VK, шапка | `https://dasdorrio.shop/?utm_source=vk&utm_medium=bio` |

Метрика берёт метку из первого просмотра визита и различает регистр, поэтому
значения пишем строчными и метку ставим на саму ссылку, а не на переход внутри
сайта. Отчёт: Отчёты → Источники → Метки UTM.

## Прямая ссылка на товар

`https://dasdorrio.shop/#ключ` открывает сразу нужный товар,
например `#drakon`. Удобно ставить в описание конкретного ролика.

## Как посмотреть локально

Через любой локальный сервер, например `python -m http.server 8765` в
папке проекта и открыть `http://localhost:8765/`. Двойной клик по
`index.html` тоже работает, но браузер может не подхватить шрифты.
После правки открывать страницу с параметром версии (`?v=2`), иначе
браузер покажет старую копию из кэша.

## Как выложить обновление

Сайт лежит на GitHub Pages, репозиторий `IlMon-dot/dasdorrio`, ветка `main`.
Всё, что попадает в `main`, через минуту появляется по адресу выше.

Проще всего — сказать агенту «выложи обновление». Вручную из папки проекта:

```bash
git add -A && git commit -m "что поменяли" && git pull --rebase && git push
```

`git pull --rebase` нужен, потому что бот цен каждый день коммитит `prices.js`.

Статус сборки: `gh api repos/IlMon-dot/dasdorrio/pages --jq .status`
(должно быть `built`). Если на телефоне видна старая версия — обновить
страницу с зажатой кнопкой или подождать пару минут, это кэш.

В репозиторий не попадают `.business/`, `Исходники/`, `.claude/`, `plans/`,
`CLAUDE.md` и `STARTER.md` — они перечислены в `.gitignore`.

## Аналитика

Счётчик Яндекс.Метрики 112528267 стоит в `<head>` файла `index.html` кодом
из кабинета (вебвизор выключен, карта кликов включена). Цели по кликам
(`marketplace_click`, `click_wb`, `click_ozon`, `click_shop`) и просмотры
товаров отправляет скрипт страницы; номер счётчика в нём указан явно.
Что считается и какие цели создать — в `.business/goals/kpi.md`.

**Если с какого-то компьютера заходы не считаются.** Открыть сайт, нажать F12,
вкладка Network, в фильтре набрать `mc.yandex`, обновить страницу и посмотреть
строку `tag.js?id=112528267`:

- `application/javascript` и около 240 КБ, затем запрос `watch/112528267` —
  счётчик работает, искать причину в фильтрах Метрики;
- `image/gif` и 43 байта, запроса `watch` нет — скрипт подменил антивирус
  (у Касперского это «Антибаннер» или «Защита от сбора данных»). Добавить
  `dasdorrio.shop` в разрешённые сайты этих компонентов или проверять с телефона.

## Подвал, плашка о Метрике и политики

Под сценой главной — подвал с обязательными сведениями о владельце сайта
(ИП, ОГРНИП, адрес, почта) и ссылками на `policy.html` и `cookie.html`.
Внизу экрана — плашка «Сайт использует Яндекс Метрику…» с кнопкой «Понятно».
Она только сообщает: счётчик работает у всех с первой секунды, основание —
законный интерес, как на dasdorrio.ru. «Понятно» прячет плашку, браузер это
запоминает (`localStorage`, запись `dasdorrio-metrika-note`).

Когда обновлять политики:
- поменялись почта, адрес или контакты — подвал `index.html` и обе политики;
- на сайте появляется новый сервис (форма, пиксель, другой счётчик) или новый
  файл cookie — сначала политики, потом сервис; список cookie в `cookie.html`
